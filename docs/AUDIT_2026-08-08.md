(`docs/field-runs/`), 73 local-CI and 40 OrbStack CI records (`ci_logs/`), the parity
report, the acceptance drill evidence, `SKILL.md`, the 10 agent definitions, and every

It records findings, not fixes. New finding IDs start at **F-63** (`SC8_PLAN.md:294`

## 1. Headline

The pipeline works. Thirteen runs, fifteen jobs, five clean PROMOTEs, one terminal RETRY,
one transient QUARANTINE later cleared, and a finding register (F-0…F-62) that is unusually
disciplined for a project this age.

The problem is not the pipeline's behaviour. It is **what the pipeline can see about
itself**:

**The gate had never gone red.** 73/73 local CI runs pass; 40/40 OrbStack runs pass; all
657 recorded steps pass, across the gate's entire recorded life. This is not a logging
artifact — `gate.sh:45` sets `overall=fail` without exiting and `:94-96` emits the JSONL
record *before* the `[ "$overall" = pass ]` exit, so a red gate would be recorded. Every
finding in the F-register was found by a field run, a review bot, or a human audit. **None
was ever found by CI.** A green signal from a gate with no demonstrated ability to fail
carries much less information than its volume suggests.

**The pipeline has already certified an information-disclosure bug as 12/12.**
`docs/field-runs/2026-08-07-issue22-cadence-method-skill.md:124-146` records a validator
that passed grader 12/12, unanimous consensus at both gates, and full falsifiability
baselines — and shipped an unconstrained `path.resolve(process.cwd(), relPath)` that read
files outside the checkout and echoed their contents into finding messages, reproduced
verbatim after the fact. The record's own conclusion: *"a 12/12 grader result certifies
criterion coverage, not correctness."*

**A frozen fixture can pin nothing, and the pack looks identical either way.** Same run,
`:148-159`: two fixtures added specifically to lock a security fix targeted paths that do
not exist, so `ENOENT` produced output byte-identical to the guard refusing. **Deleting the
guard left both fixtures GREEN.** The same sweep found roughly a dozen further rules pinned
by no fixture at all. A routine mutation sweep was recommended; no mechanism was shipped.

Three defects reproduced in this audit sit precisely in the band the suite does not
test — `parity/run-parity.js:270-274` runs each validator's CLI exactly once per pack, on
`fixtureFiles[0]`, happy path only, asserting only exit 0 and that `rubric_result` is a
string.

## 2. Confirmed defects (reproduced)

Every item below was reproduced against this checkout, not inferred.

### F-63 — prototype-key path skips the build-phase policy gate

`adws-pipeline/scripts/validators/repo-context-scan.js:27` declares `const groupedFiles = {}`,
which inherits `Object.prototype`. `dir` is derived entirely from the LLM-supplied
`file_path` (`:30-32`). For `dir === '__proto__'` (also `constructor`, `toString`,
`valueOf`, `hasOwnProperty`), `groupedFiles[dir]` is truthy, the initializer at `:35-37` is
skipped, and `.push` is `undefined`.

```
$ printf '%s' '{"plan_output":{"file_change_proposal":[{"file_path":"__proto__/x.js",…}]},
               "policy":{"allowed_paths":["src/"],"blocked_paths":["__proto__/"]}}' \
    | node adws-pipeline/scripts/validators/repo-context-scan.js -
adws-validator: execute failed: groupedFiles[dir].push is not a function
EXIT=3
```

The crash is not the finding. The `blocked_paths` / `allowed_paths` loop lives in the
**same loop body** (`:40-53`) and never completes, so a proposal explicitly inside a
blocked path produces **no verdict at all** rather than `fail`. The build-phase policy gate
is skipped, not failed. `task-normalize.js:26` already uses the correct
`Object.create(null)` pattern, so the fix exists in-repo.

*Severity: confirmed. Reachable from any plan the planner emits.*

### F-64 — `branch_name` is length-checked only, in both ship validators

`patch-compose.js:22` and `ship-mode-select.js:21` both reduce the check to
`.trim().length > 0`.

```
branch_name: "--upload-pack=/tmp/evil"  → rubric_result: "pass"   (ship-mode-select)
branch_name: "foo; rm -rf ~"            → rubric_result: "pass"   (patch-compose)
```

These are the validators SKILL.md documents as the pre-git gate. The value reaches git:
`adws-shipper.md:49,62` run `git push -u origin {branch_name}`, and `SKILL.md:130` runs
`git worktree add … -b adws/{jobId}/{slug} {target_branch}` — where **`{slug}` is never
defined or sanitised anywhere in SKILL.md or the references.**

*Severity: confirmed **validation gap**; exploitability **partially** confirmed. The
validators execute no git, so this is not a demonstrated injection. What is demonstrated is
that a leading-dash value lands in argv option position and that nothing in the spec
constrains how the agent quotes the value for the shell. The gate that exists to be checked
before git should not pass values that are unsafe where git receives them.*

### F-65 — unbounded spread in `drift-sentinel`

`drift-sentinel.js:244` — `const max = abs.length ? Math.max(...abs) : 0;`

```
50,000 entries  → ok
200,000 entries → THREW: Maximum call stack size exceeded
```

Reachable from `entropy-gate.js` over an append-only `entropy_history.jsonl` that nothing
truncates. It degrades to exit 3 rather than a wrong verdict, but the verify-phase gate
becomes un-runnable. This is the only spread-over-unbounded-array in the codebase; there is
also **no input-size limit anywhere** — all ten CLI wrappers call `fs.readFileSync` with no
cap.

### F-66 — five agents must write files and hold no write tool

`adws-critic`, `adws-advocate`, `adws-grader`, `adws-verifier` and `adws-planner` all
declare `tools: Read, Grep, Glob, Bash`. Each body instructs the agent to write files —
`adws-critic.md:51` and `adws-advocate.md:44` say *"Write EXACTLY one file"*;
`adws-planner.md:17-21` requires three. Their only writer is a `Bash` heredoc. The Advocate
runs at `model: haiku`.

Three field runs record haiku single-file writers returning the verdict in their final
message instead of writing the file (`issue106:57-62`, `issue103:58-62`, `issue105:91-102`),
mitigated only by prose at `SKILL.md:66-73`.

*Causation calibrated: the missing tool is the **most likely** mechanism, not an
established one — `Bash` can write those files, so the frontmatter alone does not prove it.
The fix stands on its own merits: an agent instructed to write a file should hold a write
tool.*

### F-67 — predictable temp path in the parity harness

`parity/run-parity.js:146` built `os.tmpdir()/adws-parity-cli-input-<pid>.json` and wrote it
with `writeFileSync` — deterministic name, world-writable directory, follows symlinks, no
`O_EXCL`. A local attacker who pre-created that path as a symlink obtained an
arbitrary-file overwrite and unlink at the privilege of whoever ran `make ci`.
`parity/sc3-micro-drill/run-tests.js:68` already used `mkdtempSync` correctly.

*Fixed in M-5a/A4.*

### F-68 — `install.sh` destroys user edits silently

`install.sh:35-37` runs `rm -rf "${SKILLS_DIR}/adws-pipeline"` then `cp -R`, and
`cp .../adws-*.md "${AGENTS_DIR}/"`, with no backup, no prompt, and no diff. Any local edit
to an installed skill or agent is destroyed without notice. The header calls this
"idempotent"; it is idempotent and lossy.

### F-69 — `safeReadJson` conflates unreadable with absent

`execution-report.js:80-86` catches every error and returns `null`, so `EACCES`, `EISDIR`,
a truncated write and a syntax error are indistinguishable from "never written" —
rendering downstream as *"wrote no readable phase_manifest.json"* (`:345-361`). For a tool
whose stated purpose is tamper-evident evidence, this is the same class SC-8/F-55 closed
from the other side.

## 6. Security posture: what holds

Recorded here so remediation does not disturb it.

- **No `child_process`, `eval`, `Function()`, `vm`, network egress, or `process.env` in any
  shipped validator.** `PARITY_REPORT.md:156-168` asserts built-ins only; `requires-lint`
  re-asserts it every CI run. `execution-report.js` requires only `fs` and `path`.
- **Prompt-injection rule landed in all 10 agent specs** (SC-2 C4): repository content,
  issue text and diffs are DATA, never instructions; embedded directives are reported as
  findings, not followed.
- **Secret-redaction rule landed in all 10 agent specs** (SC-2 C5). Note this is an
  LLM-honoured rule with no mechanical enforcement.
- **Protected-branch refusal verified live** — `DRILL_EVIDENCE.md:50`: the refusal happened
  *before* any staging or commit; adversarial refutation failed to overturn it.
- **Worktree isolation held** in every run that reported on it.
- **CI container is well-scoped**: no `--privileged`, no `--cap-add`, no docker-socket
  mount, no credential mounts, `--user $(id -u):$(id -g)`, `-e HOME=/tmp`, `--rm`. Its one
  sharp edge is that `/repo` is mounted read-write although the container clones to a
  `mktemp -d` and never needs to write there.
- **The only network egress is `review.sh`** (Tier 3), which POSTs the branch diff to
  `$OLLAMA` — default localhost, but `OLLAMA_HOST` is an unvalidated env var. JSON is built
  with `jq --arg` and the body is passed via `curl -d @-`, so the diff never reaches the
  process table.

Two observations that are consequences of the environment rather than skill defects:
`--admin` squash-merges bypassing branch protection, and `--no-gpg-sign` on cloud-path
ships — both traceable to the org's Actions/CodeQL billing lock, which made required checks
unrunnable in 8 of 13 runs.

## 7. Two corrections to first-pass figures

Recorded because both changed the remediation plan's shape.

**Parity costs ~4 s per gate run, not 277 s.** The 277 s figure is the *cumulative sum
across all 73 recorded runs*; the latest record shows `parity:4s` of a 5 s total. Two
consequences: an anti-vacuity sweep has real budget, and `drift-sentinel`'s
env-read-at-call-time impurity — which forces process-per-fixture isolation — costs about
four seconds, not 277, so it is not worth "fixing". That impurity is in fact load-bearing:
it is what lets `guard-ablation` set and restore env around each in-process `execute()`
call.

**The duplicated agent boilerplate costs no always-loaded context.** Only `SKILL.md` is
always resident; `.claude/agents/*.md` load per dispatch and never co-load. The 9,340
byte-identical bytes across the 10 agent files are a **drift** problem, not a token
problem — the fix is a lint, not a refactor. `SKILL.md` (412 lines, ~6.9k tokens, always
loaded, of which ~125 lines are reference-grade material) is where the token win is.
